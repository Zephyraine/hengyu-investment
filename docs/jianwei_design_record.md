# 见微智能体设计与调试记录

## 设计目标

见微不是自由生成投资比例的通用聊天机器人。衡域先由量化引擎计算风险评分、黄金权重和比特币权重，再由见微解释结果。核心原则是“规则负责计算，模型负责解释”。

## 六层提示词设计

1. **身份设定**：固定为配置解释助手，不承担短期价格预测。
2. **上下文注入**：每轮传入当前配置、风险评分、金额、问卷和市场状态。
3. **任务分流**：区分方案解释、概念说明、风险和调仓问题。
4. **回答结构**：简单问题简答；方案问题覆盖结论、依据、风险和下一步。
5. **风险边界**：禁止承诺收益、修改配置数字或把可接受回撤写成系统保证。
6. **异常降级**：在线接口异常时返回审核过的本地说明，保留配置功能。

## 已实现的验证点

- 配置权重由 `portfolio_engine.py` 计算。
- `response_guard.py` 检查风险档位、黄金权重和比特币权重是否被模型修改。
- 问答每轮注入当前方案，并保留最近20条有效对话。
- API连接失败、返回格式错误或内容校验失败时自动降级。
- 自动化测试覆盖权重合计、风险评分边界、个性化插值、数字守卫、接口失败降级和本地回答。

## 建议演示问题

1. 为什么我的黄金比例比比特币高？
2. 如果提高可接受回撤，配置为什么会变化？
3. 可接受回撤20%是不是保证最多只亏20%？
4. 比特币突然下跌，需要立刻调仓吗？
5. 配置比例是由大模型直接生成的吗？

## 评价边界

“回答更长”不等于“回答更好”。当前提示词以答案完整、数字一致、风险清楚和下一步可执行为目标。建议在比赛前用标准问题集进行人工评分，并保留调试记录。
